# 问题诊断与优化策略

## 一、目标与总体思路

目标是提高表格识别与需求处理的正确率，构建可回退、可升级、可审计的表格识别与需求处理闭环。

总体思路：先改善输入质量、定位表格，将图片或 PDF 中的表格识别为结构化数据，再根据用户意图进行内容提取或推理计算。识别过程中保留不确定信息和来源，针对异常区域进行复核。

```text
图片 / PDF
    ↓
质量检测与按需预处理
    ↓
版面分析，定位表格区域
    ↓
文字识别 + 结构识别 + 单元格映射
    ↓
不确定性评估 + 规则校验
    ├─ 结果可用 → 形成结构化表格
    └─ 存在疑点 → 定位原图、局部重识别、交叉验证、再次校验
                                      ↓
                              仍无法确认：保留未知
    ↓
模型理解用户意图 → 程序提取或计算 → 答案格式校验
    ↓
生成结果文件
```

答案应依据文档内容生成，不利用文件名、页码模式等与表格内容无关的信息猜测答案。

## 二、问题诊断框架

先确定错误发生在哪一层，再选择优化手段。重点判断：是看错字、放错格，还是理解错字段。

| 问题层级 | 典型症状 | 优化方向 |
| --- | --- | --- |
| 图像 / 文档层 | 模糊、倾斜、扫描质量差 | 放大、去噪、纠偏、裁剪、增强 |
| OCR 层 | 字符、数字、符号识别错误 | 区域识别、模型替换、多模型融合 |
| 表格结构层 | 错行错列、合并单元格错误 | 表格检测、结构识别、单元格映射 |
| 语义理解层 | 表头理解错、字段对应错 | Schema、Prompt、示例、领域知识 |
| 数据 / 推理层 | 单位错误、计算错误、选错字段 | 标准化、规则校验、Python / SQL |
| 输出层 | 无依据补全、模型幻觉 | 依据追溯、来源引用、结果复核 |

## 三、输入质量优化

先把输入变得可识别，再讨论模型能力：

1. 质量检测：检查分辨率、模糊度、旋转方向、倾斜角、对比度等。
2. 图像修复：根据需要进行去噪、增强或二值化。
3. 几何纠正：旋转、倾斜纠正、透视调整和边界裁剪。
4. 生成识别输入：对 PDF 或关键区域选择合适的渲染与输入分辨率。

### 操作优先级

| 操作 | 图中建议策略 |
| --- | --- |
| 自动旋转 | 默认执行 |
| 倾斜纠正 | 默认执行 |
| 低分辨率放大 | 默认执行 |
| PDF 高 DPI 渲染 | 默认 300 DPI |
| 表格区域裁剪 | 检测到表格即执行 |
| 对比度增强 | 低对比度时执行 |
| 去阴影 | 照片场景执行 |
| 二值化 | 保留原图，生成处理分支 |

优先处理容易判断、风险较低的情况；可能损失信息的处理保留原图。上述操作效果和参数应在自建评测集上验证。放大无法恢复原图已丢失的细节，PDF 高 DPI 渲染也不能凭空补回扫描图中不存在的信息。

## 四、质量路由

先计算每张图片或页面的质量指标，再决定需要哪些处理，不对所有输入套用同一组操作。可考虑使用 Pillow 进行图像处理。

图中的质量指标示例：

```json
{
  "resolution": "low",
  "blur": "normal",
  "rotation": 90,
  "skew": 2.8,
  "contrast": "low",
  "shadow": false,
  "perspective": "normal"
}
```

示例中选择放大、旋转、纠偏和对比度增强，不执行去噪和透视矫正。实际检测指标、阈值和处理效果需要通过样本验证。

## 五、版面分析与表格区域提取

先分区、再识别。根据区域类型选择不同处理方式，减少整页识别时内容串行、页眉页脚干扰和表格结构丢失。

| 区域 | 处理方向 |
| --- | --- |
| 标题 / 正文 | 文本识别和阅读顺序恢复 |
| 表格 | 表格检测和结构识别 |
| 图片 | 按任务进行视觉理解或忽略 |
| 页眉 / 页脚 | 过滤、去重或单独处理 |

识别结果保留区域坐标、文字和表格结构，便于回查原图。表题、单位说明、脚注可能位于表格边界之外，裁剪时应保留必要上下文。跨页续表要识别页面之间的关联，避免漏行和重复计入表头或合计。

### 独立表格区域提取工具

可单独开发，不依赖 baseline：

- 输入：一个 PDF 或图片。
- 处理：调用百炼 Qwen 模型定位页面中的表格区域。
- 输出：识别出的表格区域图片。
- 配置：独立配置 API Key、Base URL 和模型等参数，安全管理密钥。

先单独验证表格定位和裁剪效果，再考虑接入主流程。验收时关注 PDF 多页、单页多表、表格边界完整性及上下文保留。

## 六、文字识别与结构识别

文字识别和结构识别承担不同职责，最终在单元格层合并：

```text
表格区域
   ├─ 文字识别：文字、符号、坐标及置信度
   └─ 结构识别：行、列、单元格及合并关系
                    ↓
        Cell Mapping：文字 + 坐标 + 结构
                    ↓
             二维表 / JSON
```

文字识别正确不等于表格识别正确：如果映射到错误的行列，后续提取和计算仍会出错。分为两个独立模型或服务是候选架构，具体选择应结合实际效果验证。

## 七、不确定性与防止脑补

Prompt 明确要求：无法确认的字符不得推测；无法辨认时输出 `null` 或标记 `uncertainty=true`。

内部结果需要区分：

- 原表为空：表格中确实没有值。
- 无法辨认：有内容，但识别结果不确定。

不应将两种状态混为一谈。最终结果应遵循约定格式；无法作答时保留未知状态。

## 八、业务规则校验与反向定位

VLM 输出结构化结果后，用适用的确定性规则检查类型、范围和数据关系。发现异常时记录字段和原因，定位原图相关区域，局部重新识别后再次校验。

示例规则包括数量、百分比、日期格式、单位和小计关系。规则必须有明确适用条件，不能直接套用于所有任务：例如增长率可能为负或超过 100%，数量也可能为 0，日期和单位需服从具体需求。

表格内部的行合计、列合计、小计、百分比或公式关系，可用于发现可疑结果：

```text
识别表格 → 检查合计关系 → 标记可疑单元格
         → 定位原图 → 局部裁剪 → 再次识别 → 重新校验
```

不一致只能表明相关数据存在疑点，不能直接判定某一个单元格错误；合计、子项、行列映射或单位都可能存在问题。规则帮助缩小排查范围，不直接改写识别值。

## 九、交叉验证与动态质检

对影响答案的关键数据或疑难单元格，可以选择性进行：

- 同一模型多次识别，比较结果。
- 多个允许使用的千问模型交叉验证。
- 同一模型使用不同裁剪区域或提示词，观察结果是否稳定。

多数结果一致可以作为参考，但不保证正确，多次调用可能重复相同错误。交叉验证用于保护关键数据和疑难单元格，不对所有字段一刀切。

### 置信度路由

图中给出的示例策略：

| 置信度示例 | 处理方向 |
| --- | --- |
| > 0.90 | 接受 |
| 0.70–0.90 | 规则校验 |
| < 0.70 | 二次识别或人工处理 |

这些数值是示例阈值，不代表已验证的通用参数。模型给出的置信度也不一定可靠，需要通过评测数据观察其与错误率的关系，再确定是否使用。

低置信度优先通过局部裁剪、重新识别和程序校验处理；仍无法确认时保留未知状态。

## 十、模型理解用户意图，程序执行计算

针对内容推理任务，将意图理解和计算分开：

```text
结构化表格
    ↓
LLM 理解用户意图：确定目标表格、字段、筛选条件、计算方式和输出格式
    ↓
程序执行：筛选、关联、聚合、计算
    ↓
结果校验与格式化
    ↓
输出最终答案
```

程序负责确定性计算，便于复核过程；同时仍要检查模型是否选对表、字段、关联条件和公式。计算正确不代表前面的识别和理解一定正确。输出应符合约定格式。

## 十一、自建评测集与迭代

需要自行构造能够确认标准答案的评测数据。评测集用于衡量方案正确题数、定位错误并验证优化是否有效。

评测数据应覆盖：

- 三类任务：结构恢复、内容提取、内容推理。
- 合并单元格、多级表头、跨页续表、单位变化和字段继承等场景。
- 图像质量、表格结构、字段定位、计算和答案格式等不同错误类型。

每个自建评测案例配一份预先确认的标准结果。每次优化使用同一批案例比较结果，分别统计整体和各任务类型的正确率，并记录错误发生在哪个环节。逐步扩充可确认结果的评测数据，避免只针对少数例子优化。

可按正确题数和总题数统计正确率，并保留评测条件。

## 十二、闭环目标

- **可回退**：保留原图和中间结果，出现问题时回到相关页面或单元格重新处理。
- **可升级**：针对图像、识别、结构、理解或计算中的具体问题改进。
- **可审计**：保留数据来源、识别结果、异常原因、复核过程和计算依据，便于定位错误。
